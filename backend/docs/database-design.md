# Database Design

PostgreSQL 16+ (tested on 18). Schema owned by **Flyway** (`src/main/resources/db/migration`); Hibernate runs with `ddl-auto=validate`. Demo data lives in `src/main/resources/db/demo` and is only applied with the `demo` profile.

## Conventions

- `uuid` primary keys generated by the application.
- `timestamptz` for instants, `date` for calendar dates.
- Enums stored as `varchar` + `CHECK` constraints (readable, easy to evolve with a migration).
- Structured JSON payloads stored as `text` (serialized by the application; never queried by content).
- `version bigint` for optimistic locking on mutable aggregates.

### `refresh_tokens`
id PK · user_id FK→users ON DELETE CASCADE · token_hash varchar(64) UNIQUE · expires_at · created_at · revoked_at NULL · replaced_by_id uuid NULL. Index `(user_id)`.

### `workspaces`
id PK · name varchar(120) NOT NULL · created_at · updated_at · version.

### `workspace_memberships`
id PK · workspace_id FK→workspaces CASCADE · user_id FK→users CASCADE · role varchar(16) CHECK IN (OWNER, ADMIN, MEMBER) · created_at · UNIQUE (workspace_id, user_id) `uk_ws_member` · index (user_id).

### `task_dependencies`
id PK · project_id · predecessor_task_id · successor_task_id · type CHECK = 'FINISH_TO_START' · created_by FK→users SET NULL · created_at.
UNIQUE (predecessor_task_id, successor_task_id); CHECK predecessor ≠ successor; FK (predecessor_task_id, project_id) → tasks(id, project_id) CASCADE; FK (successor_task_id, project_id) → tasks(id, project_id) CASCADE. Indexes (project_id), (successor_task_id).

### `task_activities`
id PK · task_id FK→tasks CASCADE · project_id · actor_id FK→users SET NULL · type varchar(40) · old_value varchar(500) · new_value varchar(500) · occurred_at. Index (task_id, occurred_at DESC), (project_id, occurred_at DESC).

### `risk_assessment_events`
id PK · assessment_id FK CASCADE · project_id · event_type CHECK IN (DETECTED, ESCALATED, MITIGATED, UPDATED, RESOLVED, REOPENED) · severity · score · revision · details varchar(500) · occurred_at. Index (assessment_id, occurred_at DESC).

UNIQUE (assessment_id, recipient_id) `uk_inbox_assessment_recipient`. Indexes (recipient_id, last_delivered_at DESC), (recipient_id, read_at), (project_id).

## Referential integrity highlights

- Project data cannot leak across workspaces: memberships reference `(workspace_id, user_id)` pairs; dependencies reference `(task_id, project_id)` pairs.
- Deleting a user is not exposed by the API; FKs are defined defensively (RESTRICT on authored data, SET NULL on assignments).

## Migration strategy

- Versioned migrations `V{n}__description.sql`, never edited after release; one migration per logical change.
- `V1__identity.sql`, `V2__workspaces_projects.sql`, `V3__tasks.sql`, `V4__risk.sql`, `V5__inbox.sql`.
- Demo seed `db/demo/R__demo_seed.sql` is a *repeatable* migration, added to Flyway locations only with the `demo` profile. It is idempotent (`ON CONFLICT DO NOTHING` / `NOT EXISTS`) and never occupies a version number, so it cannot block future `V6…` migrations.
- Flyway runs automatically on application startup (no separate Maven Flyway plugin); `FlywayMigrationIT` validates every migration against a fresh PostgreSQL container.

## MongoDB: AI generation log

Database `foresight`, collection **`ai_generations`** (Spring Data MongoDB; indexes created at startup via `spring.data.mongodb.auto-index-creation`). Not a system of record: no foreign keys, no shared transactions with PostgreSQL, best-effort asynchronous writes.

| Field | Type | Notes |
|---|---|---|
| `_id` | ObjectId | |
| `assessmentId`, `projectId` | UUID (standard representation) | references to PostgreSQL rows (not enforced) |
| `revision` | int | assessment revision explained |
| `category`, `severity` | string | |
| `configuredProvider`, `model` | string | `none`/`anthropic`; model only when the provider is enabled |
| `source`, `outcome` | string | `ANTHROPIC`/`FALLBACK`; `PROVIDER`/`FALLBACK` |
| `fallbackReason`, `errorMessage` | string | e.g. `provider_disabled`, `rate_limited`, `invalid_output` (message ≤ 300 chars) |
| `latencyMs`, `recommendedActions` | long, int | |
| `createdAt` | date | **TTL index** `ttl_created`: documents expire after 90 days |

Indexes: `assessment_created` (`assessmentId` asc, `createdAt` desc), `ttl_created`. Prompts, model output text and credentials are never stored.

## Important access patterns

| Pattern | Query / index |
|---|---|
| Authorize project access | `workspace_memberships (workspace_id,user_id)` + `project_memberships (project_id,user_id)` unique lookups |
| List tasks with filters | `tasks (project_id, status)` partial index, Spring Data `Specification`, paged |
| Load analysis snapshot | all non-archived tasks + dependencies + members of one project (bounded by project size) |
| Periodic job | `projects WHERE status='ACTIVE'` paged by id |
| Reconcile | `risk_assessments WHERE project_id=?` (all identities, active + resolved) |
| Delivery sweeper | `risk_assessments (delivery_status, next_delivery_attempt_at)` |
| Inbox listing | `inbox_items (recipient_id, last_delivered_at DESC)` + filters, paged |
| Generation history of a risk | MongoDB `ai_generations` by `assessmentId`, newest first, paged |
